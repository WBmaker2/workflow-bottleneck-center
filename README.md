# 작업 순서 병목 해결소

## 목적과 교육과정

`작업 순서 병목 해결소`는 초등 5~6학년이 공개된 선행 관계, 병렬 가능 여부, 제한 자원을 이용해 네 가지 가상 과제의 흐름을 설계하고 개선하는 정적 학습 SPA입니다. 실과·정보 교육과정 `[6실05-01]`(생활 속 문제를 해결하는 알고리즘을 다양한 방법으로 표현하기)와 연결됩니다.

앱의 시간은 교육용 가상 시간 단위입니다. 실제 작업 시간, 사람의 생산성, 개인의 능력을 측정하거나 예측하는 도구가 아닙니다.

## 30~40분 수업 흐름

1. **의뢰 접수·조건 확인 (4~5분)**: 미션 카드와 안전·품질·역할 공정성 조건을 읽습니다.
2. **관계 설계 (6~8분)**: 먼저 해야 하는 일과 함께 할 수 있는 일을 연결합니다.
3. **일정 배치 (7~9분)**: 작업을 시간축과 역할 A·B·C에 배치하고 제한 자원을 확인합니다.
4. **가상 실행·예측 (5~6분)**: 실행을 멈춰 기다림의 원인을 예측한 뒤 실제 가상 실행 기록과 비교합니다.
5. **병목 분석·수정 (5~7분)**: 선행 경로, 자원 대기, 역할 대기 중 원인을 찾아 일정을 수정합니다.
6. **개선 보고서 (3~5분)**: 최초안과 수정안을 비교하고 안전·품질·역할 공정성을 지킨 근거를 씁니다.

## 네 가지 미션

| 미션 | 가상 과제 | 살펴볼 제약 |
| --- | --- | --- |
| 과학 전시판 준비 | 자료 확인부터 인쇄·부착·최종 점검까지 준비합니다. | 인쇄 후 부착, 프린터 1대 |
| 도서 반납 카트 | 책을 분류하고 상태를 확인한 뒤 구역별로 배치합니다. | 확인 전 배치 금지, 카트 1대 |
| 교실 발표 준비 | 대본·자료·음향을 준비하고 합동 연습을 합니다. | 개별 준비 후 최종 합동 연습 |
| 환경 캠페인 부스 | 안내판·분리함 표지·동선을 준비해 부스를 엽니다. | 안전 통로 확보, 역할 교대 |

모든 미션은 5~7개의 작업과 공개된 선행 관계, 병렬 조건, 제한 자원, 안전·품질 조건을 제공합니다.

## 화면에 보이는 판단 규칙

- 선행 작업이 끝나지 않으면 다음 작업을 시작할 수 없습니다.
- 같은 제한 자원을 동시에 사용할 수 없습니다. 역할이나 자원이 부족하면 기다림이 기록됩니다.
- 안전 조건과 품질 조건을 만족하지 못하거나 필수 작업을 생략한 빠른 일정은 성공이 아닙니다.
- 참여 역할 수와 역할별 가상 작업량 차이를 함께 확인합니다. 역할의 능력을 성별·성격·신체 특성과 연결하지 않습니다.
- 병목은 단순히 가장 긴 작업이 아니라 뒤의 작업 시작을 늦춘 선행 경로·자원 대기·역할 대기로 설명합니다.
- 가장 빠른 일정 하나만 정답으로 삼지 않습니다. 안전·품질·역할 공정성을 지킨 여러 절충안이 성공할 수 있습니다.

## 가상 모델과 책임 있는 최적화의 경계

시뮬레이터는 공개된 과제 규칙을 교육용 시간 단위로 재생하는 결정적 가상 모델입니다. 결과는 실제 일정, 실제 작업자, 실제 생산성에 대한 예측이나 평가가 아닙니다. 학생은 시간을 줄이는 것만이 아니라 안전 조건, 품질 확인, 협력과 역할 공정성을 함께 지키는 변경을 찾아야 합니다.

확인·도움 요청·역할 교대·휴식은 흐름의 책임 있는 조건이며 낭비로 판정하지 않습니다. 위험 장비 조작이나 아동 노동을 연상시키는 실제 작업 지시도 제공하지 않습니다.

## 로컬 저장과 개인정보

진행 저장은 기본적으로 꺼져 있습니다. 학생이 **이 기기에 진행 저장**을 직접 선택했을 때만 해당 브라우저의 `localStorage`에 버전형 학습 상태를 저장합니다. 저장을 선택하지 않으면 새로고침 후 진행을 복원하지 않습니다.

저장 데이터에는 선택한 미션, 관계·일정·실행 결과·근거 문장만 포함되며 학생 이름이나 온라인 계정 같은 개인 식별 정보를 받지 않습니다. 저장 실패 시에도 현재 활동은 메모리에서 계속할 수 있고, 저장 내용을 지우는 선택도 제공합니다.

## 접근성·사용 안내

- **키보드**: Tab/Shift+Tab으로 이동하고 Enter 또는 Space로 버튼·체크박스·라디오를 조작합니다. 화살표 키로 native select와 라디오 선택을 바꿀 수 있습니다. 모든 작업·시점·담당 선택은 드래그 없이 가능합니다.
- **375px 화면**: 관계 설계판과 일정표는 각각 한 화면에서 확인하며, `요약 보기` 패널로 설명을 다시 엽니다. 가로 스크롤 없이 단계 흐름을 완료할 수 있도록 설계했습니다.
- **스크린 리더**: `lang="ko"`, 단계 제목, 선행 관계의 텍스트 목록, 상태 `aria-live` 안내를 사용합니다. 색상만으로 관계·대기·안전 상태를 구분하지 않습니다.
- **모션 감소**: 운영체제에서 `prefers-reduced-motion: reduce`를 켜면 `gi-pulse` 깜빡임과 자동 진행 대신 정적 윤곽선과 수동 단계 이동을 사용합니다.
- 화면 오른쪽 아래의 **업데이트 내역** 버튼에서 설계·개발 기록을 확인할 수 있습니다.

## 로컬 실행 명령

Node.js `>=22.12` 환경에서 실행합니다.

```bash
npm ci
npm run dev
npm run test
npm run test:e2e
npm run verify
```

개발 서버는 기본적으로 Vite 주소 `http://127.0.0.1:5173`에서 열립니다. `npm run test:e2e`는 빌드 후 Chromium으로 Playwright 경로를 실행합니다. 필요하면 한 번 `npx playwright install chromium`으로 브라우저를 설치합니다.

## 테스트 매트릭스

| 검사 | 명령 | 확인 범위 |
| --- | --- | --- |
| 정적 품질 | `npm run lint` | ESLint 오류·경고 없음 |
| 타입 | `npm run typecheck` | TypeScript strict 계약 |
| 단위·UI | `npm run test` | 도메인, reducer, 저장, React UI, 아키텍처 가드 |
| 파일 크기 | `npm run check:file-length` | `src`, `tests`, `e2e`, `scripts` 각 소스 499줄 이하 |
| 프로덕션 빌드 | `npm run build` | 타입 검사와 Vite `dist` 생성 |
| 통합 학습 경로 | `npm run test:e2e` | 네 미션, 키보드·모바일·저장·업데이트 내역 |
| 전체 로컬 검증 | `npm run verify` | lint → typecheck → Vitest → 파일 크기 → build |

`tests/architecture/noExternalServices.test.ts`는 외부 서비스 호출, 개인 식별 필드, 도메인 계층의 브라우저·React 의존, 시뮬레이터의 비결정성, 금지된 경쟁·생산성·휴식 문구, 시나리오 4종, 업데이트 날짜 형식을 고정합니다.

## 파일 구조와 책임

| 경로 | 책임 |
| --- | --- |
| `src/data/scenarios/` | 네 공개 미션의 작업·관계·자원·판정 조건 |
| `src/domain/` | React와 브라우저 API가 없는 순수 타입·검증·시뮬레이션·분석·평가 |
| `src/app/` | 단계 전환과 미션 상태 reducer/provider |
| `src/storage/` | 선택형 로컬 저장 adapter와 버전 검증 |
| `src/features/<stage>/` | 안내, 관계, 일정, 실행, 분석, 수정, 보고서 화면 |
| `src/components/` | 공통 버튼·상태·대화상자·업데이트 내역 |
| `src/a11y/`, `src/styles/` | 포커스·모션 보조와 토큰·레이아웃·컴포넌트 스타일 |
| `tests/` | 도메인·상태·저장·UI·아키텍처 검증 |
| `e2e/` | 실제 학습 경로와 반응형·키보드 Playwright 검증 |
| `scripts/check-file-length.mjs` | 소스 크기 제한 검사 |

### 유지 규칙

- 코드 파일은 기능별 책임을 분리하며 `src`, `tests`, `e2e`, `scripts`의 `.ts`, `.tsx`, `.css`, `.mjs` 파일은 500줄이 되기 전에 나눕니다. 검사 기준은 **499줄 이하**입니다.
- 화면이나 판정 규칙을 바꿀 때는 `src/data/updateHistory.ts`에 실제 변경 날짜(`YYYY-MM-DD`)와 짧은 내역을 추가합니다. 앱의 업데이트 내역 버튼은 이 기록을 보여 줍니다.
- 안전·품질·역할 공정성의 근거는 화면과 테스트에서 함께 확인하며, 실제 사람에 대한 승인·측정·순위를 주장하지 않습니다.

## 범위 밖 기능과 현재 계획의 경계

이 프로젝트에는 **서버, 로그인, 외부 AI, 실제 일정 통합, 온라인 협업, 학습자 순위, 학생 이름 수집**이 없습니다. 정적 앱과 선택형 기기 로컬 저장만 사용합니다.
