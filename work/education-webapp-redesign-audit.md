- `npm run build`는 2026-08-29 현재 통과했습니다. 이는 리디자인 전 기준선이며 리디자인 품질을 보증하지 않습니다.
- 로컬 Vite 화면을 `http://127.0.0.1:5174/`에서 확인했습니다. 1169px 데스크톱 스냅샷의 첫 화면 문서 높이는 2,586px, 375px 모바일 스냅샷의 첫 화면 문서 높이는 3,546px였습니다.

## 안전 리스크와 완화

- **판정 변경 위험:** 새 UI는 기존 `ScenarioDefinition`, `ScheduleDraft`, `AttemptSnapshot`, `BottleneckFinding`을 직접 사용하며 판정 함수 파일을 수정하지 않습니다. 테스트에서 기존 평가 결과와 오류 문장을 고정합니다.
- **저장 손실 위험:** `src/storage`와 reducer를 변경하지 않고, 새 표시 상태는 URL·localStorage에 저장하지 않습니다. 리디자인 후 저장 켜기/끄기·손상 데이터 회귀를 실행합니다.
- **접근성 회귀 위험:** 시각적 진행 트랙에만 의미를 의존하지 않고 현재 단계 텍스트, `aria-current`, heading 구조, 포커스 이동을 함께 유지합니다.
- **콘텐츠 과장 위험:** 결과는 가상 시간이며 생산성 평가가 아니라는 문장을 계속 표시합니다. 실제 장비 지시나 학생 음성 기능을 추가하지 않습니다.
- **자산 오용 위험:** 현재 사용 자산은 `public/favicon.svg`뿐입니다. 사실·정체성·증거 이미지를 자동 교체하지 않으며, 일반 장식 이미지가 새로 필요하지 않아 `imagegen`도 실행하지 않습니다.

## 감사 결론

현재 앱은 학습 엔진과 안전 경계는 잘 갖추었지만, 첫 행동과 단계 위치를 찾는 비용이 큽니다. 이번 리디자인은 도메인·저장·판정 모델을 건드리지 않고 공통 헤더/진행 트랙, 시나리오 맥락, 브리핑 정보 우선순위, 활동별 카드 계층, 보고 진행 상태를 개선하는 P0/P1부터 수행합니다. 구현 후 자동 테스트, 모바일·키보드 수동 검토, 실제 학습자·VoiceOver 검토 여부를 분리하여 최종 원장에 기록합니다.

### 탐지 결과와 보완

`detect.mjs`는 기존 CSS에서 상태 카드·요약 목록·진행 도움말·병목 카드에 4~5px 좌측 포인트 테두리가 반복되고, 근거 진행률이 `width` 레이아웃 속성을 전환하는 점을 경고했습니다. 의미를 전달하는 텍스트·색상은 유지하면서 좌측 포인트를 상단 경계와 배경 토큰으로 바꾸고, 진행률 채움은 `transform: scaleX()`로 전환했습니다. `EvidenceProgress`의 0%·100% transform 계약을 UI 테스트에 추가했습니다. 탐지 이후 같은 실행을 반복하지 않았으며, 수정 후에는 정적·브라우저 검증으로 결과를 확인합니다.

제품 진실은 `PRODUCT.md`에 저장소 근거와 추론을 구분해 기록했습니다. 기존 `design-system/MASTER.md`가 이미 확정한 작업판형 시각 체계를 유지했으므로 새 시각 세계·이미지·`DESIGN.md`를 만들지 않았습니다.
