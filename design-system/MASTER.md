# Workflow Bottleneck Center Design System

작성일: 2026-08-29
대상: 초등학교 5~6학년의 작업 순서 병목 학습

## 디자인 원칙

1. **먼저 할 일이 먼저 보입니다.** 화면마다 현재 단계, 지금 할 일, 성공 조건, 다음 행동을 이 순서로 보여 줍니다.
2. **판정 근거는 숨기지 않습니다.** 작업 시간, 선행 관계, 사람 수, 도구, 동시 진행, 안전·품질 조건은 요약과 상세 보기에서 모두 읽을 수 있습니다.
3. **색은 뜻을 보조합니다.** 안전·품질·기다림·선행 관계는 색 외에 라벨, 아이콘 텍스트, 선 모양, 문장으로 구분합니다.
4. **어린이의 선택을 존중합니다.** 시간 단축만 칭찬하지 않고 확인·도움 요청·역할 교대·휴식을 책임 있는 선택으로 표현합니다.
5. **작은 화면과 키보드가 기본입니다.** 375px에서 가로 스크롤이 없어야 하며, 모든 제어는 키보드와 44px 터치 영역으로 사용할 수 있습니다.
6. **가벼운 화면을 유지합니다.** 시스템 글꼴과 CSS 도형만 사용하며, 외부 이미지·폰트·분석 스크립트를 추가하지 않습니다.

## 색 토큰

기존 도메인 의미를 유지하되 새 컴포넌트는 색상 리터럴 대신 토큰을 사용합니다.

| 토큰 | 값 | 사용 |
|---|---|---|
| `--color-ink` | `#1f2a37` | 본문과 제목 |
| `--color-ink-muted` | `#526172` | 보조 설명 |
| `--color-paper-warm` | `#f5f0e7` | 페이지 배경 |
| `--color-paper` | `#fffdf8` | 학습 공간 배경 |
| `--color-surface` | `#ffffff` | 카드·입력 배경 |
| `--color-primary` | `#2363a8` | 현재 단계·주 행동 |
| `--color-primary-dark` | `#164c84` | 링크·강조 텍스트 |
| `--color-focus` | `#a33b00` | 키보드 포커스 |
| `--color-safety` | `#b4492e` | 안전 경고·필수 확인 |
| `--color-quality` | `#356f52` | 품질·완료 |
| `--color-wait` | `#986b19` | 기다림 |
| `--color-line` | `#c7d0d9` | 기본 경계 |
| `--color-line-strong` | `#9aa8b5` | 입력·버튼 경계 |

새 색상은 위 의미 중 하나로 귀속할 수 있을 때만 추가합니다. 어두운 모드는 제공하지 않습니다.

## 간격과 모양

- 기본 간격은 기존 `--space-1`부터 `--space-7`을 사용합니다.
- 입력·버튼 최소 높이는 `--control-height: 2.75rem`입니다.
- 작은 요소는 `--radius-sm`, 카드·작업 영역은 `--radius-md`, 주요 프레임은 `--radius-lg`를 사용합니다.
- 본문 읽기 폭은 `--reading-width`를 넘기지 않으며, 큰 화면에서 공백이 생기면 진행 트랙과 요약에 사용합니다.

## 화면 구성

### App masthead

`AppMasthead`는 서비스 이름, 짧은 학습 질문, 가상 시간 경계를 포함합니다. 하나의 `h1`만 사용하고, 단계 화면에서 같은 경계 문장을 반복하지 않습니다.

### Scenario navigation

`ScenarioNavigation`은 네 개의 버튼형 카드로 구성합니다. 각 카드에는 미션 제목, 한 줄 제약 요약, 현재 선택 상태를 표시합니다. 선택 상태는 `aria-current="page"`, 텍스트 `선택됨`, 토큰 색과 테두리를 함께 사용합니다.

### Stage progress

`StageProgress`는 일곱 단계의 텍스트 목록입니다. 현재 단계에는 `aria-current="step"`, 완료 단계에는 `완료`, 아직 열리지 않은 단계에는 `잠김`을 표시합니다. 진행 트랙은 탐색 링크가 아니라 현재 위치 안내이므로 도메인 상태를 임의로 변경하지 않습니다.

### Stage frame

`stage-shell`은 시나리오 제목·현재 단계·도움말·활동을 감싸는 프레임입니다. 데스크톱에서는 진행 트랙과 학습 공간을 두 열로 배치할 수 있지만, 모바일에서는 한 열로 쌓고 활동 콘텐츠를 먼저 보여 줍니다.

### Activity cards

- **브리핑:** 미션 목표 → 세 가지 핵심 약속 → `조건 확인` 다음에 작업 요약 → 상세 작업 카드. 핵심 행동을 먼저 찾되, 전체 판정 조건은 요약과 상세에서 계속 읽을 수 있습니다.
- **관계:** 의미 문장 목록 → 관계 편집기 → 학생 관계 → 보조 그래프 → `관계 확인`.
- **일정:** 보기 전환 → 작업 배치 폼 → 모바일 단계 목록/데스크톱 시간표 → 실행.
- **실행·분석·수정:** 현재 상태 배지 → 관찰·선택 카드 → 핵심 버튼.
- **보고:** 비교 요약 → 네 근거 진행률 → 단계형 입력 → 오늘 배운 점·다음 도전 → 완성.

상태 카드는 반복되는 두꺼운 좌·우 포인트 테두리 대신 1px 기본 경계, 의미가 있는 상단 경계, 배경 토큰과 텍스트 라벨을 조합합니다. 이 규칙은 색상만으로 상태를 판정하지 않으면서도 카드가 같은 무게로 보이지 않게 합니다.

### Required action

`RequiredActionButton`은 현재 단계에서 학습자가 반드시 해야 하는 한 버튼에만 `gi-pulse`와 `data-pulse="true"`를 부여합니다. `prefers-reduced-motion: reduce`에서는 애니메이션을 제거하고 3px 포커스색 윤곽선으로 바꿉니다. 비활성 버튼에도 이유 문장을 인접하게 둡니다.

### Update history

`UpdateHistoryButton`은 문서 흐름의 footer에 배치하며 `aria-haspopup="dialog"`와 `aria-controls="update-history-dialog"`를 유지합니다. 항목은 실제 ISO 날짜·구분·간단한 변경 설명을 갖습니다.

## 반응형 규칙

- **375px 이하:** 1열, 관계 의미 목록 우선, 일정 단계 목록 우선, 그래프·시간축은 숨김 또는 명시적 가로 보기 보조물.
- **376~900px:** 1열 활동 프레임, scenario navigation은 2열 버튼, 긴 표는 카드 또는 안전한 내부 스크롤.
- **901px 이상:** 진행 트랙과 학습 공간을 18rem/1fr로 배치할 수 있으며 작업 카드와 분석 카드는 2열로 배치합니다.
- 모든 breakpoint에서 `document.documentElement.scrollWidth === clientWidth`를 목표로 하고, 내부 시간표의 가로 스크롤에는 안내 문장을 제공합니다.

## 콘텐츠·접근성 규칙

- 문장은 한 문장에 한 행동만 담고, “무엇을”, “왜”, “다음에 무엇을”을 분리합니다.
- `h1`은 서비스 하나, `h2`는 현재 미션 또는 화면, `h3`은 카드 제목으로 계층을 지킵니다.
- 색에 의존하지 않고 `안전`, `품질`, `기다림`, `선행` 텍스트를 포함합니다.
- 상태 변화는 `role="status"` 또는 오류의 `role="alert"`로 공지하고 단계 전환 시 heading에 포커스를 보냅니다.
- 아이콘을 추가할 때는 장식이면 `aria-hidden="true"`, 의미가 있으면 텍스트 라벨을 함께 제공합니다.
- VoiceOver 기능·검증은 이번 범위에서 수행하지 않습니다. 일반 스크린 리더용 구조 계약과 자동 접근성 검사는 유지합니다.

## 안전·자산 경계

- 학생 이름, 로그인, 순위, 실제 일정, 외부 AI, 서버 저장, 학생 음성·녹음 기능을 만들지 않습니다.
- 기존 `public/favicon.svg` 외에 이미지가 필요해지는 변경은 먼저 자산 분류를 문서화합니다. 사실·지도·차트·로고·스크린샷은 자동 생성·교체하지 않습니다.
- 일반 장식 이미지가 학습 구조에 꼭 필요하다고 판단될 때만 `imagegen`으로 생성하고, 원본·사용 위치·대체 텍스트·생성 여부를 `work/education-webapp-redesign-assets.md`에 기록합니다. 이번 계획에서는 이미지 삽입을 추가하지 않습니다.
